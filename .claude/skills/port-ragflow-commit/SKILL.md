# RAGFlow 提交跟进

这是 Claude 与 Codex 共用的流程入口；用户本次指令和 [AGENTS.md](../../../AGENTS.md) 优先。
按请求完成评估或移植。移植交付包括行为适配、适用验证、必要文档和明确的未完成项。

## 基准与范围

默认上游 checkout 为本仓兄弟目录 `../ragflow`，可用 `RAGFLOW_REPO` 覆盖。
先确认该 checkout 的 remote 指向预期上游，再 fetch 并记录 `origin/main` SHA；无法刷新时说明基准时点。
`origin/main` 用于检查后续演进，目标代码取用户指定提交的 `git show <commit>:<path>`，不用本地工作树代替。
用户指定其他基准时遵循该基准；默认围绕指定 commit 的问题与改进意图评估、移植，
包括由其直接启发、在本地同一问题链上有证据支持的调整，不扩展为无关重构。

以目标 SHA 的逐文件 diff 为准；PR 标题和描述只作线索，冲突时以代码为准。
评估覆盖完整 diff 的功能足迹、我方已有接口，以及相关 revert / re-land / 后续修复链。
已回退的改动以有效 re-land 或修复链评估，交代与原请求的差异；必要前置修复纳入说明，
会改变目标或兼容性的范围变化再澄清。不把 WIP、功能回退或假成功桩搬入本仓。

## 等价之后仍须比较改进价值

**“本地已有等价行为”只完成了功能判断，不能据此结束跟进。** 对每个实质改动，先查清上游
解决的问题、采用的机制和本地活动调用链，再分别判断行为覆盖与实现质量；接口存在、
正常路径输出相同或已有测试通过，都不足以证明没有值得跟进的改进。

比较与该改动有关的维度：边界与失败语义、并发和资源生命周期、性能与调用成本、
结构复杂度、可维护性、可观测性、测试覆盖及后续对齐成本。根据代码、调用方、测试或
必要的运行证据说明收益与代价；不因上游更新就认定更优，也不因本地抽象不同就停止比较。

| 判断结果 | 处置 |
|---|---|
| 本地存在行为缺口 | 补齐缺口，并按本地契约适配 |
| 行为等价，上游实现更优 | 说明具体优势与迁移代价，采用值得引入的机制或结构，保留有价值的本地能力 |
| 上游方案不能直接套用，但思路有本地价值 | 把思路映射到本地同一问题链，指出当前薄弱点、拟调整内容和验证方式，完成有依据的本地改进 |
| 行为等价且无值得引入的改进，或本地方案更合适 | 保留现状，给出等价证据、比较过的上游优势及不采纳理由 |

例如，本地已能返回正确结果，上游引入批处理、失败重试或统一清理时，仍须检查本地是否存在
重复调用、恢复缺口或资源泄漏风险；确认有收益后按本地架构调整，而不是以“功能已有”跳过。

结论必须落到当前代码和实际使用条件。证据不足时继续查调用链或做针对性验证；环境受限则
标明待验证项，不能归为“已等价，无需处理”。仅评估任务交付改进结论与建议；已授权移植时，
范围内有证据支持且收益值得的改进继续实现和验证。收益不足的改动不为制造 diff 而实施；
超出本次目标的启发明确另列，不擅自实施。

## 按改动选择参考

| 涉及内容 | 阅读与处置 |
|---|---|
| Python 生产代码 | [Python 适配](references/python.md)：框架、async、逐接口删除判据、兼容入口和测试 |
| Go `cmd/`、`internal/` | [Go 适配](references/go.md)：只在本次提交涉及 Go 或用户点名时处理 |
| 上游 `web/` | 前端是独立 `web` 仓，默认另排；用户授权同批时确认实际 checkout、目标版本与当前上游契约差异，核实本仓是否有同等页面、路由和调用链，再按本仓现行 API 契约适配。新接后端接口时区分合同测试与隔离环境中的实际请求、业务码及读回；无法运行时明确未验收项 |
| 文档 / CI / 工具链 | 同样比较覆盖与质量；已有设施时评估上游是否补强验证或降低维护成本，复用适合的机制，不重复建设等价 harness |
| 相似历史问题 | 按接口或提交号查 [历史判例](references/cases.md)，无需通读 |

## 验证与交付

按 [AGENTS.md 验证表](../../../AGENTS.md#验证) 及所选栈验证，修复本次引入的失败；只读评估与纯文档不触发全套 Python 门禁。
报告采用的上游 SHA、实际行为变化、保留的本地适配、跳过项理由和本次验证证据。
对已等价项补充实现质量比较与处置；区分直接移植、受上游启发的本地改进及有依据的不改动，
不能只用“本地已有／已等价”作为跳过理由。
结构性映射变化更新 [RAGFLOW_PORTING_MAP](../../../docs/enterprise-identity-mcp/RAGFLOW_PORTING_MAP.md) 对应项；程序状态按所属账本维护。

用户要求提交时用 conventional commit，标题不提上游来源，不加 `Co-Authored-By`；Go 与 Python 通常分开提交。
暂存前逐 hunk 核对归属，同文件混合修改不能靠关键词猜测归属；`internal/*.md` 不暂存。
不自动写持久记忆；用户明确要求记录记忆时，遵循该环境的记忆写入规则。
