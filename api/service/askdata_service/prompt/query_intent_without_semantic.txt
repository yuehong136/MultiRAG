# 图表类型及其适用场景参考 (通用知识库，用于辅助选择)
* **折线图 (Line Chart):**
    * **核心用途:** 展示数据随时间或连续序列变化的趋势。常用于分析指标随时间维度的变化。
    * **例如:** "过去一年销售额的变化趋势", "每日用户活跃度曲线"。
* **柱状图 (Bar Chart):**
    * **核心用途:** 比较不同类别或组之间的数值大小（指标），或显示项目的排名。通常一个轴是维度，另一个轴是指标。
    * **例如:** "不同产品的销量对比", "各部门预算金额", "销量最高的五个城市"。
* **饼图 (Pie Chart) / 环形图 (Donut Chart):**
    * **核心用途:** 显示各部分（维度成员）占整体（某个指标的总和）的比例构成。适用于类别数量较少的情况。
    * **例如:** "市场份额占比", "用户来源构成", "不同操作系统用户比例"。
* **散点图 (Scatter Plot):**
    * **核心用途:** 展示两个数值变量（通常是两个指标，或一个指标一个数值型维度）之间的关系或相关性。
    * **例如:** "广告投入与销售额的关系", "用户年龄与购买频率的关联性"。
* **面积图 (Area Chart):**
    * **核心用途:** 类似于折线图，但更强调数量和体积随时间或类别的变化，可用于展示累积或堆叠的趋势。
    * **例如:** "不同产品线随时间变化的销售额贡献占比（堆叠面积图）", "网站访问量随时间的变化（突出总体趋势）"。
* **指标卡 (KPI Card / Metric Display):**
    * **核心用途:** 突出显示单个或少数几个关键绩效指标 (KPI) 的当前值或聚合结果（如总数、平均值）。通常用于展示用户最关心的核心数字。
    * **例如:** "当前总销售额", "今日新增用户数", "计算机学院副教授和讲师的总人数"。
* **明细表 (Detailed Table):**
    * **核心用途:** 展示原始数据记录或多维度、多指标的详细信息。当用户需要查看具体的字段值，而不是聚合统计时适用。适用于基于原始字段值的筛选（例如 '部门为计算机学院'），而非基于聚合结果的筛选（例如 '找出人数大于5的那些部门'）。
    * **例如:** "列出所有计算机学院副教授和讲师的姓名和专业方向", "显示过去24小时内所有订单的详细信息"。
* **聚合表 (Aggregated Table):**
    * **核心用途:** 对数据按一个或多个维度进行分组，并对每个组进行指标的汇总计算（如求和、平均值、计数）。它同样适用于需要对聚合后的结果进行筛选或排序的场景。
    * **例如:** "按产品类别统计总销售额和平均订单价", "显示每个部门的教师人数，按职称分类统计", "找出副教授人数超过5人的部门"。
* **透视表 (Pivot Table):**
    * **核心用途:** 允许用户将数据进行交叉分析和重塑。选择维度作为行和列，在交叉点上显示聚合指标。适合多维度探索。
    * **例如:** "按地区（行）和产品类别（列）展示总销售额", "分析不同职称（行）在各个学院（列）的人数分布"。

# 指示
1.  仔细阅读并理解用户提出的问题内容。
2.  识别用户核心的数据分析需求（例如：是想看总数、比较大小、分析趋势、查看明细、分组聚合还是交叉对比等）。
3.  参考上面 “# 图表类型及其适用场景参考” 部分的通用知识。
4.  **务必**从系统实际支持的图表类型列表中选择一个最能满足用户核心数据分析需求的图表类型。以下是一些常见需求下的图表选择**指导建议**：
    * 如果用户需求是快速了解一个核心汇总数字，优先考虑**指标卡** (如果系统支持的图表类型列表中包含此类型)。
    * 如果用户需求是查看详细的多列原始数据，优先考虑**明细表** (如果系统支持的表类型列表中包含此类型)。
    * 如果用户需求是按维度分组并查看汇总统计，考虑**聚合表** (如果系统支持的图表类型列表中包含此类型)。
    * **如果用户的提问中包含了对聚合结果的筛选条件（例如，“哪些部门的人数超过5人？”，“找出平均销售额大于1000的产品”），这本质上仍然是分组聚合分析，因此应优先选择聚合表或透视表，而不是明细表。**
    * 如果用户需求是进行多维度交叉对比分析，考虑**透视表** (如果系统支持的图表类型列表中包含此类型)。
    * 如果用户需求是比较不同类别下的指标值，考虑**柱状图** (如果系统支持的图表类型列表中包含此类型)。
    * 如果用户需求是分析数据随时间变化的趋势，考虑**折线图** (如果系统支持的图表类型列表中包含此类型)。
    * 如果用户需求是了解各部分占整体的比例，考虑**饼图** (如果系统支持的图表类型列表中包含此类型)。
    * 即使需求不完全清晰，也需要基于对用户问题的最佳理解，从系统支持的图表类型列表中选择一个最相关的图表。
5.  **生成一句简洁明了的推荐理由 (recommendation_reason)**，解释为什么选择的图表类型适合用户的分析需求。例如：
    * "选择指标卡是因为用户希望快速了解一个核心总数。"
    * "推荐柱状图，因为它最适合比较不同类别下的数值大小，能清晰展示各分类的指标对比。"
    * "折线图能清晰展示数据随时间变化的趋势，符合用户观察动态变化的需求。"
    * "明细表适用于用户需要查看多列详细原始数据的场景，可以展示所有相关字段。"
    * "聚合表能按用户指定的维度对数据进行汇总统计，满足分组查看聚合结果的需求。"
    * "透视表提供了灵活的多维度交叉分析能力，适合当用户需要从不同角度探索和对比数据时使用。"
    * "饼图直观地展示了各部分占整体的比例构成，适合用户理解组成结构。"
6.  你的输出**必须且仅能**是一个JSON对象，格式如下：
    `{"recommended_chart": "图表类型名称", "recommendation_reason": "选择该图表类型的简要理由"}`
    其中 "图表类型名称" **必须**是系统支持的图表类型列表中的一个元素。"recommendation_reason" 应该是你根据指示第5点生成的说明。不要添加任何额外的解释或文字在JSON对象之外。
