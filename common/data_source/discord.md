# Discord 消息同步

Discord 连接器保留按 `batch_size` 合并消息的行为：每份文档使用该批第一条消息的
`DISCORD_{message_id}`，正文包含整批消息，更新时间取批内最大值。现有数据没有独立的
成员消息身份映射；增量时间窗口、消息删除或批次大小变化都可能改变分组。

## 读取与资源释放

同步 worker 在异步调用链中消费同步文档生成器。Discord 客户端运行在专用线程的事件循环中，
按需读取下一条消息；批次处理期间该事件循环保持运行。正常结束、读取异常和显式关闭生成器
都会关闭客户端、结束后台任务并回收线程。登录失败会向调用方传播，不再无限等待 ready。

读取保留 server/channel 配置范围、起止时间以及普通频道、活跃线程和归档线程的历史遍历；
历史接口使用 `limit=None`。`validate_connector_settings()` 只检查 token 是否存在，
不证明 token 有效、Gateway 可用或拥有频道权限；这些必须在实际读取中验证。

同步配置接受 Web 表单的 `server_ids` / `channels` 数组及旧配置的逗号分隔字符串。
`channels` 为空或缺省时回退到旧键 `channel_names`；空白项被移除，非法 server ID 或配置形状
会使本轮失败，不会丢弃错误 ID 后扩大读取范围。同步任务默认合并批次大小仍为 1024。

## 删除同步仍不可用

Discord 未注册到后端可信删除清单能力和 Web 删除开关中。历史配置即使保存了
`sync_deleted_files=true`，同步 worker 也不会据此枚举或删除 Discord 文档。

按完整历史重新分批所得到的首消息 ID，不能可靠代表已入库文档。例如原批次为
`1+2`、`3+4`，删除消息 `1` 后重分批变成 `2+3`、`4`；按新首 ID 清理会删除仍含有效正文的
旧文档。删除非首消息也可能移动后续批次，同时残留已删除正文。频道权限减少和不可见的
配置范围也不能被视为完整空清单。

因此保持现有身份与数据，不自动迁移、重建或清理。删除同步继续等待兼容的身份及完整范围
方案；异步读取修复不构成开启删除同步的依据。

受控回归见 [test_discord_connector_async.py](../../tests/unit/test_discord_connector_async.py)：
覆盖异步 worker、同步调用、原有合并身份、时间和频道范围、线程历史、登录/读取/入库失败、
提前关闭及删除能力门禁。这些测试替换 Discord SDK 边界，不使用真实 SaaS 凭据；真实 bot、
Gateway、message-content intent、频道/线程权限和服务端分页仍需独立验收。
