# Skills 调整计划：Go源码跟进，Python兼容与增强

2026-10-04。状态：源码调查与调整计划已完成；下列架构、协议、数据迁移和增强尚未实施。
旧实现及其测试证据保留在[PROGRESS](PROGRESS.md)，不作为新方案已完成的证明。

## 已确定方向

- Go以上游源码为主体，保留服务划分、实体、方法、调用关系和核心协议，控制本地补丁。
- Python原生实现RAGFlow适用能力与对外行为，可以比Go更强；内部设计不反向约束Go。
- Python、Go是可替换后端，各自管理数据。生产继续Python；切换通过显式资产导入导出。
- 不要求两端实时共库、共索引、共operation。可以共用基础设施集群，但数据命名空间隔离；
  不能只分Skills表，却继续混用File树、对象地址或未经映射的租户/模型记录。
- Web共用展示组件，数据层明确区分上游核心与Python扩展；按能力显示，不取最低能力交集。
- Agent自动执行仍不在当前范围；只读MCP发现、读取和分发可以独立推进。

## 本次复核结论

上游空间领域为两张Skills表加通用File树，技能/版本主要是目录；不是当前自建七表、
不可变版本、active-version、generation与统一operation API。现有Go实现需要替换其领域骨架。

上游更新空间用PUT，配置/搜索/索引为Skills根下端点，上传通过Files；我方是嵌套资源、
PATCH与原子包上传。空间列表虽同为`GET /api/v1/skills/spaces`，DTO也不兼容。
上游空间删除已有202，但返回deleting/space_id，没有可用于轮询的operation ID。

上游仍存在删除失败标deleted、后台继承请求context、重建提前删旧索引等问题。
不能为源码相似撤销租户校验、错误真实性和文件/索引一致性。必要修复必须独立、可定位。
冻结Skills搜索保存rerank配置但未实际执行；当前严格rerank是本地增强。
现Go模型适配忽略query标志，也须在收敛时补齐查询/文档embedding语义。

Python七表可先保留为私有实现。稳定的上传校验、发布验证、任务恢复、删除补偿无需为了
Go收敛而重写；但兼容入口不能额外要求上游没有的revision、operation、active或强制SemVer。
Python更强的内部历史记录不等于可以改变核心客户端可观察到的更新、版本选择和错误语义。

## 源码基线与维护办法

本次Go收敛从原始目标源码加必要后修开始，继续遵守既定冻结上限。上游remote分支已经
前进，不因此偷偷扩大本轮范围；后续新批次再固定新的SHA和能力清单。
不整体复制冻结最终树所依赖的FileService拆包、模型工厂和引擎大重构。

追踪目标仍为`4ee0702aed1395e88fccf4b8b0aea68ce76b9d62`，冻结上限仍为
`519e7d98a5651564d4e35d6648f006cba4baaf4f`；原生Go删除采用范围内
`5a7d7771a3efafbf99651f358189c07e0ff395ba`的解耦方向，其他后修逐项登记。

核心文件保持entity/dao/handler/service/router的上游对应关系，保留必要来源和许可信息。
每个本地差异记录：上游SHA/路径/符号、本地路径、原因、测试、可删除条件。
模型绑定、PostgreSQL命名、存储和Milvus适配尽量放边界；不把整套领域重写藏进adapter。
实际源码清单及后修证据保存在本地上游对照笔记，不复制为产品运行合同。

后续每项上游提交必须形成四栏结论：Go源码处置、Python能力/等价修复、消费者影响、验证证据。
仅Go内部重构可以判Python无需变化，但须说明理由；涉及行为、安全或持久状态的改动必须
追到Python对应路径。新的现代Skills参考也按版本/日期评估，不做未经验证的自动依赖升级。

## 协议分层与切换

| 层 | 目标 |
|---|---|
| RAGFlow兼容核心 | 保留上游空间、Files目录/版本、配置、索引、搜索与CLI调用语义；Python实现同一核心 |
| Python资产扩展 | 保留不可变发布、显式活动版本、可靠任务、严格rerank等增强，使用明确扩展入口/能力声明 |
| Web/CLI消费模型 | 适配真实字段、结果和状态；不伪造version ID、operation ID、完整总量或成功状态 |

建议将当前新增资产协议显式命名为`multirag-assets-v1`，兼容入口使用
`/api/v1/skill-assets`；上游核心继续使用`/api/v1/skills`。具体新增路由先做冲突清单。
迁移期间原`/skills`保留现协议，先让已知消费者移到明确入口，之后才切换核心。
若证实尚无部署/外部消费者，可整套切换而不留无用兼容层；不能仅根据未push推断无人使用。
同一路径不同语义不得猜payload自动回退；必须明确协议选择或完成消费者迁移后切换。

Python兼容层须处理Files树到内部资产的真实映射、上游默认版本选择、模型引用、同步/异步
完成语义。现有全树Files禁写保护不能简单移除：兼容入口经领域授权和一致性流程处理，
Python扩展内部资产仍受保护。仅隐藏目录名不能代替资源级授权。

模型沿用上游embd_id/rerank_id消费形式，在服务端精确解析本地模型；保留大整数的字符串
表示。完整旧引用存在歧义时明确拒绝，不按显示名挑第一个。不得复制现query标志被忽略的问题。

当前依赖与虚拟环境均为FastMCP/fastmcp-slim 4.0.0b3、MCP2.0.0；本机已有Skills
providers和list_skills/download_skill/sync_skills。官方latest此次为
[4.0.10](https://github.com/PrefectHQ/fastmcp/releases/tag/v4.0.10)。不用升级作为原型前置；
正式版升级独立提交，并跑现有入站/出站、modern/legacy完整兼容门禁。

FastMCP现成provider读本地目录，不能直接替代数据库/对象存储资产库。资源URI要区分
同名不同空间与固定版本；manifest与附件读取须一致，删除中资产每次访问都隐藏。
验证list_skills/get_skill_manifest/download_skill真正消费我们资源，不能仅测resources/list。
SDK本身不提供我们的租户权限、版本治理、SQL补偿或索引一致性。

Python优先增强顺序：标准包互操作与元数据保留 → 版本diff/发布回退及来源追踪 →
只读MCP分发 → 固定来源更新预览/显式升级 → 检索质量和批量管理。
回退采用发布旧快照或选择旧版本，不改写已有版本字节。远程源下载、凭证和可执行内容的
范围在该阶段单独设计；不把“支持发现/下载”呈现成“可以自动执行”。

## Web体验计划

- 技能库首页：以发现、检索、筛选和导入为主，展示来源、说明、可用版本和可检索状态。
  后端类型、generation、lease、operation UUID不作为普通用户的主信息。
- 详情页：默认说明与适用场景，文件树/正文预览、版本历史、变更比较按需展开；
  Python显示发布/回退等真实增强，Go遵循目录/默认版本行为，不把最高版本伪装为显式active。
- 导入：选择来源 → 预览目录/元数据/校验问题 → 选择空间和发布行为 → 查看结果。
  清楚区分文件已保存与索引可用，索引失败提供真实重试，不以绿色“上传成功”覆盖失败。
- 检索：普通输入与筛选优先；模型、字段权重和调试结果放到高级配置。避免要求用户先理解
  BM25或vector_weight才可使用；切换后端不丢失普通浏览/下载能力。
- 长任务与删除：紧凑的进度和可执行错误反馈，重试保留原任务上下文；实现无operation的
  上游模式时轮询真实资源状态，不生成假的持久任务。
- 继续使用项目设计令牌、共享组件、TanStack Query和中英i18n；键盘/窄屏/明暗主题及
  多张截图contact sheet审阅。先交互原型和真实数据验证，再扩大视觉改造。

## 数据与验收边界

不因“尚未push/部署”就删除七表、回滚迁移或清对象。先只读盘点已应用迁移及各环境事实。
有存量则迁移租户、原始字节、manifest、版本和用户可见元数据；模型引用显式映射；
索引在目标重建，不复制物理集合或租约/任务记录。未完成任务先收敛或形成明确恢复清单。
Python独有的active/不可变历史不能无损映射成Go默认最高版本时，导出保留扩展信息并报告
差异，不静默丢历史或声称无损迁移。旧资产保留只读，清理是独立后续步骤。

验收分三组：上游核心两端共同合同；Python扩展；消费者/迁移。公共组检查真实HTTP与业务码、
租户边界、Files树/版本、模型身份、上传后索引失败、删除SQL/对象/索引读回、分页和重启恢复。
替换此前跨端直接读同一库/同一集合的测试；保留其中摘要、删除、故障等可复用断言。
按仓库要求跑Python verify/integration/smoke、Go build/vet/独立main、Web门禁和两端浏览器；
实际外部模型、特定索引引擎、MCP和生产切换分开记录，不用历史测试数代替新架构验收。
