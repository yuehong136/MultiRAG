# 按标题分块（Title chunker）

Title chunker 用于数据处理流程中的标题分块。当前运行入口为
[TitleChunker](../core/flow/chunker/title_chunker/title_chunker.py)，参数定义在
[common.py](../core/flow/chunker/title_chunker/common.py)。前端在节点表单中提供层次结构
（Hierarchy）与分组（Group）两种模式，输出 `chunks`。

## 模式与正文归属

- **层次结构**：构建标题树，分块携带上级标题路径，适合法规、合同、技术规范等需要保留
  章节位置的文本。默认会将上级标题的直接正文带入子块。
- **分组**：按选定标题层级划分章节，并合并相邻短章节以保持内容连贯；不主动补入上级
  标题路径，适合书籍、手册和报告。自动选项使用识别结果中的高频标题层级。

前端在层次结构模式提供以下两个开关，默认均关闭：

| 配置 | 实际行为 |
|---|---|
| 分离上级标题正文（`include_heading_content`） | 将上级标题的直接正文单独成块；子块保留标题路径与自身正文，不重复上级正文。并非丢弃正文。 |
| 将首个分块设为全局上下文（`root_chunk_as_heading`） | 对结构化 `json` / `chunks` 输入，当输出多于一块时，将首块文本添加到其余每块之前，然后移除独立首块；只有一块时保留原块。适合首段说明主体信息的简历等文档。 |

例如 H1「项目」下有简介、H2「安装」下有步骤：关闭正文分离时，安装块包含「项目、简介、
安装、步骤」；开启时，简介形成「项目、简介」块，安装块包含「项目、安装、步骤」。
文本、Markdown、HTML 输入当前提前返回文本块，不执行首块上下文处理。
首块上下文开关会改变结构化输入的块数和文本，启用前应检查首块是否确实适合作为所有后续块的公共内容。

UI 只在层次结构模式展示这两个开关，但当前序列化仍保留隐藏值，后端的首块文本前缀处理
由两种模式共用。若先开启首块上下文再切换分组，该设置仍可能生效；需要纯分组输出时，
先在层次结构模式关闭它再切换。本文不改变已保存流程的参数或运行行为。

## 标题级别与正则规则

前端层次结构默认 H3，分组默认自动。可选 H1–H5 来自默认规则中的最大级别，
不是后端固定的五级限制；“添加正则表达式”会在当前规则内增加一级，“添加规则”增加
另一套匹配规则。规则变化后应检查所选层级是否仍存在。

后端结合规则、标题布局与 PDF outlines 识别标题。层级参数按当前文本中实际识别到的标题
层级取第 N 级，超过现有层级时使用最深一级；没有标题时按现有正文路径处理。
正则匹配、文档布局和输入结构会影响结果，不保证所有文档都能恢复原始目录树。

## 输入与使用边界

当前 [输入 schema](../core/flow/chunker/title_chunker/schema.py) 接受 `markdown`、`text`、
`html`、`json` 和 `chunks`。文本输入按行处理，不等同于完整 HTML DOM 标题解析。
图片、表格等非文本记录单独保留，可能中断连续文本的分组。

Token chunker 输出的 `chunks` 属于可接受输入，因此本地没有“放在 Token chunker 后必定
报错”的规则；但前序切分可能已经损失标题与正文的联系，是否适合串联应检查实际输出。
本指南描述代码契约，不代表特定文件、模型、解析服务或完整入库流程已验收。

数据库 schema 升级使用本地 SQLAlchemy / Alembic 流程，见
[数据库迁移指南](database-migration.md)，与分块参数配置分开处理。
