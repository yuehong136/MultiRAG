# MultiRAG 知识库使用指南

> 面向需要创建、维护和验收知识库的使用人员。页面名称以当前部署的 Web 界面为准；不同环境可用的模型和解析服务可能不同。

## 先看完整流程

![从文件到可检索知识的五步流程](/Users/xldu/project/multirag/docs/knowledge-base-guide-assets/01-ingest-flow.png)

图 1：知识库从文件到可检索内容的主线。资料准备和后续应用配置分别位于这条主线的前后。

| 环节 | 你在决定什么 | 会影响什么 | 何时算完成 |
| --- | --- | --- | --- |
| 准备资料 | 哪份文件是可信的现行版本，文字和结构能否被读出 | 后续所有切片的事实与完整性 | 文件内容、版本、使用范围已确认 |
| 创建知识库 | 主题、语言、嵌入模型、可见性 | 哪些资料放在一起、如何向量化、谁能在列表看到 | 名称和模型已核对 |
| 选择解析方式 | 如何从文件提取文字并形成切片 | 标题、段落、表格、图片与答案能否保留 | 一份样本解析后切片可读 |
| 上传并解析 | 将文件存入库并建立检索索引 | 文档是否真正进入可检索状态 | 状态已完成、切片数大于 0 |
| 审阅切片 | 修改错误内容，启用或停用内容 | 系统实际可能召回哪些事实 | 关键事实与来源正确 |
| 检索测试 | 用真实问题验证召回，必要时调整参数 | 正确切片能否出现、排序是否合适 | 目标问题命中正确来源 |
| 应用使用 | 在助手等应用中引用知识库 | 最终回答如何使用检索内容 | 在应用里另行验证回答 |

**最短可用做法：**准备一份文字清晰的现行文件；创建知识库并选好嵌入模型；保持默认 General 解析；在“文档 → 导入文档”上传；确认“已完成”且切片数大于 0；打开切片核对内容；用一条有答案、一条无答案的问题做检索测试，检查命中来源与误召回。先完成这一轮，再扩大文件量或开启额外能力。

**判断顺序：**效果不好时可从回答往回排查，但调整应从更靠前的根因入手。原文没有答案，调检索参数不会补出事实；解析把表格读乱了，调阈值也不会还原表格。

## 1. 准备资料与划分知识库

### 1.1 先整理来源文件

- 确认文件所有者、适用范围、生效日期和版本。过期制度与现行制度同时启用，容易让检索返回互相冲突的依据。
- 优先选择文字可复制、标题层级清楚、表格有表头的文件。默认 PDF 解析器包含 OCR，但扫描清晰度仍会影响识别；图片、录音和视频还要确认相应的视觉或语音处理能力，并用样本验证。
- 删除或注明草稿、重复副本、仅供内部审批的附件。文件名要能帮助维护者识别来源，但不能代替正文中的版本说明。
- 将一个难以解析的大文件拆成结构清晰的章节或独立文件，通常比盲目缩小切片更容易定位错误。保留原始文件，以便重做解析和核对引用。
- 上传前确认资料可以进入当前知识库。“团队可见”会扩大同团队成员对知识库的访问和部分操作范围，选择前应确认资料与协作权限。

### 1.2 什么时候分成多个知识库

当资料的**使用人、更新周期、语言或嵌入模型、主要解析方式**明显不同，优先分库。例如“在售产品说明”和“历史产品归档”应避免长期混在同一可用范围；结构化 FAQ 与复杂扫描合同也可以分开，便于分别验收。

同一个库可以包含多份文件，单篇文档也能单独改解析方式。不要只因文件格式不同就机械分库。若之后要把多个库一起检索，先确认使用相同的嵌入模型；当前服务会检查这一点。

### 1.3 按资料类型准备样本

| 资料类型 | 起步做法 | 特别要检查 |
| --- | --- | --- |
| TXT、Markdown、HTML、普通 DOCX | 先用 General；保留标题、列表和自然段 | 标题是否跟随正文，编号与数字是否完整 |
| 可选中文字的 PDF | 先用 General 和默认 PDF 解析器；简单单栏文件可对照“纯文本” | 页序、表格、脚注、标题与正文是否混乱 |
| 扫描 PDF、照片、图片 | 先取一页或一张做识别样本；确认部署环境有 OCR 或视觉模型 | 数字、姓名、印章旁文字、图片说明是否识别正确 |
| CSV、XLS、XLSX | 先确认是普通说明表、逐行记录表，还是问答表，再选方法 | 表头、列对应关系、空行、合并单元格 |
| PPT、PPTX 演示文稿 | 上传一份样本，检查逐页内容 | 图表中的文字和跨页上下文；讲稿备注不能假定已入库 |
| 邮件、音频、视频 | 邮件优先用 EML，音频先试已验证的 WAV、MP3 或 FLAC；视频先做小样本 | 邮件正文、转写文字、视频关键事实是否实际成为切片；可上传不代表该格式可解析 |
| 旧 DOC、Pages 等旧格式或少见格式 | 优先转换成 DOCX、PDF 或可读文本后再上传 | “能上传”不等于“能成功解析” |

对于大批量资料，先用每种类型各一份做完整验收，再批量导入。不要只凭扩展名或上传成功提示判断可用。

## 2. 创建知识库：先确定长期共用的设置

打开“知识库管理”并点击“创建知识库”。创建页主要填写名称、描述、语言、嵌入模型和权限设置；初始解析方式为 General。

| 设置 | 如何选择 | 后续影响 |
| --- | --- | --- |
| 知识库名称 | 用业务主题和范围命名，例如 Product_FAQ_2026；当前创建界面要求名称以字母开头，只含字母、数字和下划线，最多 100 字符 | 便于选择和维护；中文用途写在描述里 |
| 描述 | 写清资料主题、适用人群、版本负责人和更新频率 | 减少误用旧库或错误范围 |
| 语言 | 选资料的主要语言，而非只看使用者提问语言 | 影响文本处理与检索；跨语言查询另做测试 |
| 嵌入模型 | 选已启用、适合资料语言的模型；计划联合检索的库保持一致 | 决定向量空间；已有切片后不能直接切换 |
| 权限设置 | 在“仅自己可见”和“团队可见”中按实际协作范围选择 | 影响列表展示与上传准入；团队成员能否做其他操作还取决于账号角色和具体接口 |

“仅自己可见”不能单独承担敏感资料的完整隔离：当前部分文档和切片操作只校验团队成员关系，并非都核验这项可见性。涉及敏感资料时，由管理员确认实际成员权限与访问范围后再入库。

**嵌入模型要在第一次解析前确认。**如果后续确实要换模型，建立使用新模型的知识库，重新导入并解析样本，对照检索结果和应用引用，确认可用后再停用旧库。不要先删除仍被应用使用的旧库。

若创建页没有可选的嵌入模型，先让管理员配置并启用模型，再进行入库。创建后可在“设置”核对模型；列表本身不显示模型。

## 3. 选解析方式：决定怎样形成切片

解析不仅是“读取文件”，还会生成切片并建立检索索引。切片是后续检索的基本内容单元。**先选符合资料结构的方法，再调细节参数；先看解析结果，再扩大数量。**

### 3.1 常用内置方法怎么选

| 方法 | 适合先试的场景 | 准备与验收重点 |
| --- | --- | --- |
| General | 普通说明、制度、混合文字、首次试入库 | 通用起点；核对标题、段落、表格和关键事实 |
| Q&A | 已整理成“问题—答案”的 FAQ | 问答必须成对；XLSX 前两列为问与答且不设表头，TXT/CSV 和 Markdown 也有各自格式要求 |
| Table | 首行是表头、之后每行是一条记录的 CSV/XLS/XLSX | 列数应一致、表头不重复；核对每行是否保留列名含义 |
| Paper | 学术论文 PDF | 检查章节、公式、图表与引用是否还在正确上下文 |
| Book、Laws | 长篇章节或条款型资料 | 检查章节层级、条款编号、跨段引用；先用一份样本比较 General |
| One | 内容很短且整份文件应作为一段上下文 | 长文件会让切片过大、召回不精确，不作为默认方法 |

**问答表与普通表不要混用。**例如一张“产品型号／保修期／地区”表，先试 Table；一张“用户问题／标准答案”表，先试 Q&A。Q&A 表格不要额外插入表头；Table 则需要表头。格式不符合方法预期时，先整理源表，比继续调阈值更有效。

### 3.2 专用方法与自动分流

界面还提供以下专用方法。方法名称只是用途提示，选择后仍要验收实际切片。

| 方法 | 何时考虑 | 使用前先确认 |
| --- | --- | --- |
| Manual | PDF、DOCX 操作手册的章节边界较清楚，General 把标题与正文拆乱 | 它是手册结构解析方法，不等于在界面手工编辑切片；用一章对照测试 |
| Resume | 确有简历检索需求，并已确定个人信息的使用范围 | 用经授权的 PDF／DOCX 样本核对姓名、经历、时间，不把解析结果直接当人事结论 |
| Presentation | PPT、PPTX 或演示版 PDF 是主要资料 | 逐页核对文字与图表；讲稿备注不能假定进入切片 |
| Picture | 图片或视频中的画面事实需要被检索 | 视觉识别能力、清晰度及关键数字的识别结果 |
| Audio | 语音内容需要转成可检索文字 | 语音模型和实际文件格式；先试 WAV、MP3、FLAC 样本 |
| Email | 邮件正文需要入库 | 优先 EML；讨论邮件应标注最终决定和日期 |
| Knowledge Graph | 普通切片正确，但实体关系和多跳问题仍难回答 | 图谱生成是后续额外任务，见第 8 节 |
| Tag | 有专门标签体系并使用支持的存储环境 | 常用的 Milvus、Infinity 部署会拒绝该方法，不作为普通问答知识库起步方法 |

图片或视频会转入 Picture 路径，音频转入 Audio，演示文稿转入 Presentation，邮件转入 Email；因此知识库选了 General，也不能假定这些文件按普通文字方式解析。图片、音频和视频能否形成有用切片，取决于识别模型与实际内容。Pages 虽可能被归入演示文稿类型，当前演示解析器未把它列为支持格式，建议先转成 PPTX 或 PDF。

**选择方法的最终依据是切片和检索测试。**方法名称只说明设计用途，不保证某份文件的页序、表格或事实会被正确提取。

## 4. 配置解析：参数分别影响什么

进入知识库“设置”后，再为后续导入的文件选择解析方式与参数。创建时固定从 General 起步；若资料结构明确属于问答、行记录或论文，创建后先改设置，再上传正式文件。

**设置的作用范围要先分清：**知识库设置是以后导入文档的默认值。上传时，每篇文档会保存一份自己的解析配置；之后修改知识库设置，不会自动重做已上传的文档。旧文档要改变结果，需在文档的“分块方法”中核对或修改配置，再明确发起重新解析。重新解析可能清除已有切片和人工编辑，操作前保留源文件与重要修改记录。

### 4.1 General 的起步值与调参顺序

当前默认配置为：目标切片大小 512 tokens、分隔符为换行、PDF 解析器为 DeepDOC、自动关键词和自动问题数量为 0、图片和表格上下文窗口为 0。它们是起步值，不代表所有资料的最佳值。

| 参数或选项 | 它影响什么 | 什么时候调整 | 改完看什么 |
| --- | --- | --- | --- |
| 目标切片大小 | 一段检索内容大约容纳多少文字；512 是目标而非严格上限 | 答案总被切开时适当增大；命中段太长、混有多个主题时适当减小 | 一个问题所需事实是否完整、结果是否过长或互相干扰 |
| 分隔符 | 给文本拆分提供边界线索 | 原文有稳定章节标记、问答分界或特殊换行时，先在样本上尝试 | 标题是否仍跟着正文、列表和条款是否被错误拆开 |
| PDF 解析器 | PDF 中的文字、版面、表格与图片如何被抽取 | 默认结果有错字、列串行、阅读顺序错乱时，对照其他解析器 | 原文关键页与切片逐段对照，尤其是数字和表格 |
| 目录提取 | 基于已有切片额外生成目录索引，不会修复正文的标题或顺序 | General 文档章节清楚、且有可用聊天模型时做样本测试 | 生成目录是否对应原文；正文切片仍需单独核对 |
| 图片／表格上下文窗口 | 将附近文字补给已识别的图片或表格 | 图注、说明与图表分离，单看图表切片不知道含义时 | 图表相关问题能否找到完整背景，是否混入无关段落 |
| 自动关键词／自动问题数量 | 为切片补充可能的术语或问法，需要调用聊天模型 | 切片内容正确、但同义词或用户问法难以命中时，小范围试用 | 生成内容是否准确，解析耗时与模型开销是否可接受 |
| 自动元数据 | 按模板和模型从文档抽取字段 | 需要按产品、地区、版本等稳定字段筛选，且源文档确有这些信息时 | 字段值是否准确且一致，再用于筛选 |
| Excel 转 HTML | 在 General 中尽量保留表格结构 | 表格既有说明段落又有复杂单元格时，和 Table 方法做样本对照 | 表头、行列与单位是否仍对应 |

**推荐调参顺序：**先确认原文与解析出的文字一致，再确认切片边界，最后才尝试关键词、问题、重排或阈值。分隔符并非所有格式的“遇到就强制切一片”开关；不同解析方法有自己的切分逻辑。

当前 General 界面的可输入范围：目标切片大小 1—2048，自动关键词数 0—30，自动问题数 0—10，图片／表格上下文窗口 0—256。范围是界面约束，不是推荐取最大值；先从默认值或小范围开始，对照内容与解析成本。

设置界面还能看到“子分块用于检索”“子分块分隔符”“重叠比例”。当前知识库设置页保存时不会持久化这三个字段，因此不要把它们当作知识库级的有效调参手段。单文档“分块方法”弹窗的提交路径不同，若确需使用，应先以一份文档验证保存值、重解析后的切片及检索结果。

### 4.2 PDF 选哪种解析器

| PDF 情况 | 起步选择 | 何时更换或处理源文件 |
| --- | --- | --- |
| 可复制的普通正文，章节和表格不复杂 | 默认 DeepDOC | 若版面错乱，可用“纯文本”做对照；以实际切片为准 |
| 简单单栏、纯文字 PDF | 默认或“纯文本”对照 | “纯文本”主要读取文字层，不负责扫描件 OCR |
| 扫描件、复杂双栏、图文混排 | 默认先做少量页面样本 | 识别不准时检查扫描清晰度、页方向及可用的 OCR／视觉能力，再比较其他引擎 |
| 表格或公式是核心答案 | 至少抽查一张典型页 | 列名与数值错配时，优先换可编辑的表格源文件、人工整理或对照解析引擎 |

界面可能列出 MinerU、Docling、OpenDataLoader、TCADP 等引擎。能否正常运行取决于当前部署、模型和文件特征；先用同一份样本比较切片，不要凭名称批量切换。若 PDF 本身是低清扫描件，换解析器也可能无法恢复丢失的文字；此时应取得清晰原件或先校对识别文本。

### 4.3 表格、问答和长文档的特别选择

- **逐行查记录**：选 Table，源文件首行写清列名，每行保持同样列数。CSV 用逗号、TXT 用制表符；空列、重复表头、错位行要先清理。验收时用“型号 + 地区 + 指标”等组合问题，核对行与列没有串位。
- **标准问答**：选 Q&A，先规范问题与答案的对应关系。XLSX 前两列直接放问与答，不加表头；TXT／CSV 用两列逐行存放问与答，优先用制表符分隔并检查编码；Markdown 可以用标题作为问题。一个答案若包含前提、例外和有效期，应在答案内写完整。
- **跨章节长文档**：先试 General，并看章节标题是否随正文进入切片；论文 PDF 可对照 Paper，章节型资料可对照 Book 或 Laws。对“答案跨两章”的问题，先考虑改写源文档的摘要或增加明确交叉引用，再考虑进阶索引。
- **结构化标签**：Tag 方法并不是普通文件的通用解析方法；当前常见部署不支持时会被拒绝。若只是需要筛选产品、地区或版本，先用稳定的文档元数据。

## 5. 上传与解析：确认资料真的进入检索

在知识库的“文档”页选择“导入文档”，可以选文件或文件夹。当前界面每批最多处理 32 个文件、单文件最多 1 GiB；大量文件应分批，并逐批核对列表数量。不要把“上传成功”“开始解析”和“可以检索”当成同一个状态。

“创建时解析”默认开启。上传完成后，界面会另发起解析请求；若解析请求失败，文档仍可能留在列表中，需要对该文档手动发起解析。关闭“创建时解析”则先上传，之后在文档列表中选择“开始解析”。当前界面的批量上传成功标记可能覆盖本批所有文件，实际仍须核对返回的文档数量、列表和每篇文档状态。

| 看到的状态 | 含义 | 下一步 |
| --- | --- | --- |
| 未开始 | 文件已进入列表，但尚未形成切片 | 核对分块方法后点击开始解析 |
| 运行中 | 后台任务处理中 | 等待并查看进度；长时间不变时查看任务详情与服务状态 |
| 已取消 | 此次处理未完成 | 查明取消原因，再决定是否重新解析 |
| 已完成 | 解析任务结束 | 继续检查切片数量、内容、可用状态和检索结果 |
| 失败 | 任务报错 | 查看状态详情或日志，按报错修复源文件、模型或解析方法后重试 |

![文档解析验收示意](/Users/xldu/project/multirag/docs/knowledge-base-guide-assets/02-document-check.png)

*图 2：解析验收示意图，非系统截图。状态“已完成”后，还需核对切片与关键事实。*

**一次导入的最低验收：**文档列表有预期数量；目标文档显示已完成；切片数量大于 0；随机抽查标题、关键数字、表格和结论；至少一个真实问题在检索测试中命中正确来源。已完成但 0 个切片，仍不能视为可用。

同名文件再次上传通常会产生带序号的新文档，**不会覆盖旧文档**。重新解析旧文档读取的是系统保存的旧文件，也不会自动读取你电脑上修改后的版本。更新资料应按第 9 节的版本替换流程处理。

## 6. 检查和整理切片：把错误留在检索前解决

打开文档后，逐页或逐条对照原文与切片。页面可搜索切片、按可用状态筛选，并可对单条切片修改正文、关键词、问题或图片，也可新增、批量启用、停用和删除切片。PDF、图片、视频、DOCX、XLSX、PPTX、TXT、Markdown、CSV 等可在页面预览；不支持预览的格式，请有下载权限的人员或资料负责人提供原件对照。先用少量代表性样本检查，再决定是否批量操作。

| 检查项 | 理想结果 | 发现问题时 |
| --- | --- | --- |
| 标题与出处 | 切片能看出属于哪份文档、哪一节 | 调整源文档标题结构或分块方式，再重解析样本 |
| 事实完整性 | 一个答案所需前提、数值、单位和例外同处可理解的上下文 | 修正文档，或针对样本调整目标大小与分段 |
| 表格 | 列名、数值、单位、行对象一一对应 | 整理源表，比较 Table、General 或其他可用解析器 |
| OCR 和版面 | 页序正确、文字无明显识别错误 | 换清晰原件、校对文本或对照 PDF 引擎 |
| 可用状态 | 当前有效版本被启用，旧版或错误片段被停用 | 先停用冲突内容，再重新测试同一组问题 |
| 人工编辑 | 补充的关键词、问题、元数据准确且可追溯 | 记录改动；重新解析前先保存人工劳动成果 |

**局部有错**可以先停用或修正单条切片，再立即重测。**整篇过期**应停用整篇文档。文档级停用会同步影响其切片；重新启用文档时，原先单独停用的切片也可能重新启用，务必复查。若原文件已有系统性问题，修正源文件再导入新版本更稳妥；直接改切片不便于下次重解析继承。

需要按产品、地区、时间等筛选时，先定义字段含义和填写规范。可以在文档切片页右侧信息面板进入人工元数据标注，保存后刷新核对。知识库设置中的自动元数据抽取需要模板和模型，批量使用前抽查错误率。当前文档列表的“管理元数据”弹窗对新增或编辑字段值存在保存问题；人工修改请走文档详情的信息面板，并以刷新后的值为准。重解析确认框中的“应用元数据设置”勾选值目前未传入实际解析操作，不能用它推断元数据已更新。

## 7. 检索测试：判断“找不到”发生在哪一层

进入目标知识库的“检索测试”，确认当前库名称，用一组固定问题反复测试。每次只改一个变量，并记录问题、预期来源、实际命中、参数和结论。**检索测试看的是找到了哪些切片；最终回答还会受应用中绑定的知识库、提示词和上下文设置影响。**

建议至少准备以下问题：

1. **直接提问**：原文明确写着的事实，例如“产品 A 的保修期是多久”。
2. **换一种说法**：不复述原文术语，例如“坏了多久内可以保修”。
3. **精确查数值**：型号、金额、日期、条款号、单位。
4. **查表格组合条件**：地区 + 型号 + 版本，确认行列不串。
5. **跨段问题**：结论依赖前提或相邻段落。
6. **冲突版本问题**：旧版与新版都存在时，只命中当前有效资料。
7. **无答案问题**：库里确实没有的事实，检查是否出现容易误导的高相关切片；应用是否会编造回答，要到应用侧另测。

![检索结果核对示意](/Users/xldu/project/multirag/docs/knowledge-base-guide-assets/03-retrieval-check.png)

*图 3：检索结果核对示意图，非系统截图。先看来源和切片内容，再看分数与参数。*

### 7.1 先读结果，再动参数

每条结果先看**文档名、切片正文、是否当前版本、是否回答了提问、是否缺少前提**。界面显示的百分比分数是排序和筛选线索，不是经过校准的“答案正确概率”；不同检索模式的分数也不宜直接横比。某些后端在未启用重排时，向量分或文本分可能显示为 0，即便相关检索路径实际参与了召回。因此不要只凭一个分数判断失败。

若结果为 0，先确认请求没有报错、目标库和文档处于可用状态，并清掉上次遗留的文档或元数据过滤。清除过滤后，再手动点击一次搜索并核对结果；页面自动重搜可能仍使用旧过滤。当前页面有时会把请求异常呈现成 0 条结果；可由管理员查看浏览器请求、控制台或服务日志。

### 7.2 常用模式和参数怎么选

当前默认使用融合模式，相似度阈值 0.2、Top-K 1024、向量相似度权重 0.3、不启用重排或知识图谱。它们是界面初值。纯向量模式在当前页面置灰；可用的稀疏和混合模式适合做对照试验。

当前页面允许的范围是：相似度阈值和向量相似度权重 0—1，Top-K 1—2048，每页显示 1—100。范围只表示可输入，不意味着把数值调到边界会更好。

| 控件 | 想解决的问题 | 先做的对照 | 容易误判的地方 |
| --- | --- | --- | --- |
| 相似度阈值 | 低相关内容太多，或正确内容被挡掉 | 固定问题与模式，逐步升高或降低阈值 | 越高通常越严格，也可能漏掉正确切片；不同模式分数不直接等价 |
| Top-K | 候选切片数量不够，正确片段进不了后续阶段 | 固定问题、模式和页大小，比较调整前后的最终来源与排名 | Top-K 是候选上限；增大不能修复源文档缺内容或解析错字 |
| 每页显示数量 | 页面一次呈现多少条结果，也可能影响后端处理候选的窗口 | 固定其他参数，对照最终来源与排名 | 不等同于 Top-K，变化后的结果需重新验收 |
| 融合／稀疏／混合 | 同义表达与精确词、编号的匹配表现不同 | 同一问题依次比较来源与排名 | 当前融合模式的界面权重调整并未按所填值作用于后端，别把滑块变化当作已生效 |
| 混合权重 | 精确词和语义的比重需要有控制地对照 | 在混合模式下一次只改一小步 | 先确认正确切片确实存在；权重不能挽救错位表格和缺失事实 |
| 重排模型 | 正确片段已出现在结果中，但排序靠后 | 固定问题、模式、Top-K 和页大小，对比启用前后的排名 | 需要可用重排模型并增加处理开销；未召回答案时无效 |
| 关键词扩展 | 用户问法与原文术语差距大 | 用少量真实同义问题对照 | 会调用聊天模型，生成的词可能带入噪声 |
| 跨语言搜索 | 提问和资料语言不同 | 同一事实用两种语言测试 | 依赖相关翻译或扩展模型，先核对扩展是否准确 |
| 文档／元数据过滤 | 缩小本次探索范围 | 清空过滤并手动重搜做基线，再单独加入一项 | 当前路径对过滤组合及阈值的处理并不完全一致，不可用作权限隔离依据 |
| 知识图谱 | 实体关系、多跳问题需要额外线索 | 先确认图谱任务已生成数据，再做样本对照 | 只打开开关不会自动让普通切片变成图谱 |

对于**型号、合同编号、错误码、条款号**等精确词，先试稀疏或混合模式，并核对同名旧版。对于**自然语言改写**，重点检查语义检索和重排。对于**表格数值**，先确认列与值在切片中正确配对；换模式解决不了解析出的错表。

当前稀疏检索路径对通用过滤条件的处理与其他路径不一致；元数据和文档过滤的组合也不宜当作严格交集。带明确文档过滤时，还可能绕过通常的阈值后处理。凡是要求只返回某份资料或严格隔离内容的场景，应在实际应用层验证约束，不能只用检索测试中的筛选框证明。

“向量相似度权重”在当前 Milvus 路径、尤其未配置重排时，不一定改变你看到的排名。优先比较**模式、正确切片是否存在、阈值和重排**，不要把这个数值当作首要修复手段。

**检索测试的设置属于试验页面状态。**如果应用或智能体也需要相同表现，还要到对应应用配置中设置并重新验收完整回答；测试页调好了，不代表应用自动继承。

## 8. 进阶能力：先有基本可用的切片

### 8.1 图谱与分层摘要

知识图谱适合实体、关系和多步追问，例如“某产品由哪个团队维护，该团队负责的服务又依赖什么”。它需要在普通解析之外完成相应图谱生成任务，并检查实体与关系是否正确。源文档角色、名称本来就不一致时，应先规范资料。

分层摘要适合篇幅长、章节明确，需要先定位主题再找细节的资料。它需要额外生成摘要层；不是上传后自动得到。表格类材料和部分表格型 PDF 可能被跳过。启用前先用样本确认摘要没有漏掉限制条件与数字。

这两类能力会增加处理时间和模型调用，适合在普通切片已经正确、却仍有跨章或多跳问题时加入。不要用它们替代基本的文档校对。

### 8.2 数据源同步与自动导入

若知识库绑定外部数据源，先约定同步范围、更新频率、版本标识与负责人。一次同步后仍按“文档数量 → 解析状态 → 切片 → 检索”验收。当前界面中已绑定数据源卡片的“自动解析”开关显示状态不可靠；不要只看开关外观，实际检查导入文档是否解析完成。

### 8.3 影响体验但不是第一步的选项

高亮只改变结果展示，不能改善召回。PageRank 和标签集依赖额外条件，当前常用部署下不作为使用人的常规调参方案；标签数量也没有在设置页提供有效控件。流程编排入口尚不能作为本指南的稳定入库路径。优先把源资料、解析、切片与基本检索做好。

## 9. 资料更改后，怎样安全更新

更改操作前先保存原始文件、记下当前可用文档和一组基准问题。变更后重新执行第 5—7 节的验收。下表按变化的根因选择处理方式。

| 发生了什么变化 | 建议操作 | 要避免的误区 |
| --- | --- | --- |
| 原文件改了内容或版本 | 将新文件作为新文档上传并解析；对照同一组问题，确认后停用旧版，随后按保留规则清理 | 重新解析旧文档不会读取电脑上的新文件；同名上传也不是覆盖 |
| 只是旧文档解析参数不合适 | 在该文档的“分块方法”中调整并重新解析样本；先记录人工切片修改 | 只改知识库设置不会自动改变这份旧文档 |
| 之后的新文件都需要新参数 | 改知识库设置，先上传一份样本验收，再批量导入 | 不要假定旧文档会一起重做 |
| 一小段内容有误或过期 | 暂时修正或停用单条切片并重测；随后修正源文件并安排版本替换 | 下次重新解析可能覆盖人工切片修改 |
| 整份文档过期或与新版冲突 | 停用旧文档，确认当前版本能被检索；更新应用引用后再删除旧版 | 重新启用旧文档可能同时启用此前单独停用的切片 |
| 新增产品、地区、版本筛选 | 先定义元数据字段和取值规则，逐份标注并验证，再用过滤测试 | 不一致或错误的字段会使正确内容被排除 |
| 需要换嵌入模型 | 新建使用目标模型的库，重导样本、对照效果并迁移应用绑定 | 已有切片的库不能直接靠界面改模型完成向量迁移；联合检索需同一模型 |
| 只调整检索参数 | 保留固定测试集，逐项改动并记录；应用侧另行配置和复测 | 检索测试参数不自动同步到应用 |

对于重要业务资料，推荐按“**新版本入库 → 检查解析和切片 → 对照检索 → 停用旧版 → 应用侧复测 → 再清理**”执行。资料有生效日期时，正文与元数据都应写清日期；单靠文件名中的“最新版”无法长期避免冲突。

## 10. 常见资料场景：从一份样本开始

以下是起步方案，不是对所有文件一概适用的规则。每个场景都应先找一份代表性文件，完成“解析状态 → 切片 → 检索”的闭环，再批量导入。

### 10.1 产品说明、操作手册和制度文件

**资料特点：**章节、操作步骤、注意事项和例外条件并存。先用 General，保持清楚的一级、二级标题；操作步骤中的前置条件和限制要写在步骤附近。若检索只找到“可办理”却漏掉“不适用地区”，先检查两个条件是否被切进不同片段，必要时调整源文档结构或目标切片大小。

**推荐测试：**直接问办理方法，再问“不满足条件时怎么办”“哪个版本适用”。核对来源章节与生效日期。过期手册要停用或从可检索范围移除。

### 10.2 客服 FAQ、标准话术

**资料特点：**每条有明确的用户问题和标准答复。优先把源文件整理成 Q&A 所要求的格式，再上传样本。把适用条件、例外和升级处理写进答案；不要把“详情见附件”作为唯一答案。不同问法可能指向同一答案，可先测试语义召回，再决定是否补充切片问题或关键词。

**推荐测试：**原句、口语改写、错别字或简称、无答案问题各一条。发现回答命中旧话术，先处理版本冲突，而不是继续降低阈值。

### 10.3 型号、价格、规格和地区对照表

**资料特点：**答案依赖同一行的多个列。表头清晰且每行一个记录时先试 Table；混有大量说明、合并单元格和注释时，先整理源表，必要时对照 General 的 Excel 转 HTML。金额、日期和单位要作为文字或列名明确保留，避免只留裸数字。

**推荐测试：**组合两个或三个筛选条件，例如“华东地区的型号 B，在 2026 版中的保修月数”。逐条核对列名和值，特别检查空值、重复型号与不同版本。

### 10.4 合同、法规、论文和长篇材料

**资料特点：**章节层级、条款号、引用和脚注影响含义。先挑典型章节验证 General；论文 PDF 可对照 Paper，条款或长篇章节可对照 Laws、Book。扫描件还要先验 OCR。长文档不必一开始就开启进阶摘要或图谱；先看普通切片是否保留条款前提和编号。

**推荐测试：**精确条款号、跨章节例外、脚注限定、一个资料中不存在的问题。对于法律或合同解释，检索结果只提供资料依据，仍要由相应责任人核定正式口径。

### 10.5 图片、扫描件、幻灯片、录音和视频

**资料特点：**文字需要从画面或语音中识别。扫描 PDF 先试带内置 OCR 的默认解析器；图片、视频和音频要确认视觉或语音处理能力，再拿包含关键事实的一页、一张、一段做样本。图片和视频可能进入 Picture 处理路径，音频进入 Audio，演示文稿进入 Presentation；不能套用普通文本文件的切片预期。PPT 讲稿备注中的关键事实应移入幻灯片正文或另存文字文件。邮件优先用 EML；其他格式先转换并验收。

**推荐测试：**图片中的型号与数字、幻灯片图表标题、音频中的专有名词和时间、视频里的画面文字。识别错误时优先提供清晰原件、人工转写或校订文本；单纯增加 Top-K 不会修正转写错误。

### 10.6 邮件归档和持续同步资料

**资料特点：**主题相近、日期密集，容易包含来回讨论与未定稿结论。先区分最终决定与讨论过程，必要时生成一份经确认的摘要文件；邮件专用方法只解决读取结构，不会替你判断哪封邮件代表最终版本。同步资料要固定核对新增数量、失败记录、版本和切片。

**推荐测试：**询问“当前决定是什么”“何时生效”，确认不会把早期讨论误当政策。自动同步后抽查最新与旧版的启用状态。

### 10.7 中英混合、缩写和跨语言提问

**资料特点：**同一概念有中文名、英文名、缩写或产品代号。先在源文档首次出现处写明全称与别名，再用两个语言问同一事实。若原文切片正确，但另一种语言问法命不中，可试跨语言检索或关键词扩展，并检查扩展词是否失真。

**推荐测试：**中文问中文资料、英文问英文资料、交叉语言提问以及缩写提问。模型与语言配置应在建库时一并考虑；已有切片后换嵌入模型需要迁移。

## 11. 效果差时怎么排查：从结果倒推根因

先保留一条失败问题、期望答案和期望文档，逐层往回查。每解决一层就用**同一问题**重测，避免同时改解析、阈值和模型后无法判断哪个动作有效。

### 11.1 四步定位法

1. **原文有没有明确答案？**没有就补源文件、确认版本或承认该问题不在知识库覆盖范围；不要通过生成相似文本“补答案”。
2. **切片里有没有准确答案？**没有就看解析状态、切片数、可预览格式的原文预览、OCR、表格对应关系和分块边界；不支持预览时请有权限的人员提供原件对照。先改源文件或解析方法，再重解析样本。
3. **检索能不能召回这条切片？**不能就核对文档与切片是否启用、是否选对知识库、是否留有过滤条件；随后再比较提问措辞、模式、阈值、Top-K 和重排。
4. **应用拿到正确切片后能不能正确回答？**若检索已命中，转到应用检查知识库绑定、应用自身检索设置、传入上下文、提示词与答案引用。把检索结果和应用回答分开记录。

### 11.2 现象、原因与优先处理

| 现象 | 先查什么 | 优先处理 |
| --- | --- | --- |
| 选不到知识库 | 当前账号、可见性、团队范围与应用绑定 | 找到正确库与访问身份，再讨论检索参数 |
| 文件上传失败 | 扩展名、文件名、单文件大小、批量数量、权限或存储报错 | 缩小为单文件样本；旧格式转为稳定格式；重试后核对列表 |
| 提示上传成功，列表缺文件 | 本批实际返回的文档数量，是否有部分失败 | 分批补传缺失文件，逐个核对，不以批量成功提示为准 |
| 文件在列表，但一直“未开始” | 是否关闭自动解析，解析请求是否失败 | 核对分块方法后手动发起解析 |
| 长时间“运行中”或“失败” | 文档状态详情、处理日志、所需解析与识别模型 | 用同类小样本复现；修文件或环境问题后重试 |
| 显示“已完成”但切片为 0 | 源文件是否有可提取内容、方法是否适配、识别输出 | 对照原文与解析方式；扫描件试 OCR 路径或提供文字版 |
| 切片乱码、错序、漏数 | 原件质量、PDF 阅读顺序、OCR 与表格抽取 | 换清晰源文件或解析器；对重要数字逐项校对 |
| 切片里有答案但搜不到 | 文档与切片启用状态、知识库选择、过滤条件、请求是否报错 | 清空过滤并手动重搜，确认无请求错误，再调模式与阈值 |
| 正确切片排得很后 | 切片内是否有清楚主题词，候选是否包含它 | 优先修标题与上下文；再试混合模式、关键词或重排 |
| 搜到的内容来自旧版 | 同名文档副本、旧版启用状态、日期字段 | 停用旧版，核对新版切片和应用结果 |
| 命中正确切片但回答仍错 | 应用的库绑定、上下文截取、提示词和引用 | 在应用侧复测与调整，保留检索命中证据 |
| 开启过滤后结果异常 | 元数据值、过滤组合、所用检索模式 | 先无过滤验证，再逐项加入；不要用测试过滤作为权限边界 |
| 改了知识库参数但旧文档没变化 | 文档自己的解析配置与是否重新解析 | 在目标文档上确认配置并重解析；先备份人工修改 |
| 改了电脑里的文件但回答仍是旧内容 | 是否只对旧文档点了重解析 | 上传新版本、完成验收后停用旧版 |

**遇到 0 条结果时先排除系统错误。**当前检索测试页面可能把请求失败显示成空结果；若同一时刻多个已知可答问题都突然无结果，请管理员先看浏览器请求、控制台或服务日志，并检查服务和模型，再决定是否调阈值。

### 11.3 不同问题对应的修改层级

- **事实错或缺失：**修改源文档；需要立刻止损时先停用错误片段或旧文档。
- **事实读错或切断：**更换更清晰的源文件，调整解析方法、目标大小或表格结构，重新解析并复核。
- **事实存在却难召回：**先排除停用和过滤，再对照检索模式、阈值、候选数、重排与术语表达。
- **检索正确而回答不正确：**检查应用自身配置、输入上下文和回答约束。
- **批量任务不稳定：**缩小为单个典型文件定位，再按格式或来源分批处理，记录失败文件清单。

## 12. 每次交付前的验收清单

- [ ] 来源可信、版本和生效范围明确；旧版不会与现行版同时误用。
- [ ] 知识库主题、语言、嵌入模型和可见性符合使用场景。
- [ ] 每种文档类型至少有一份样本完成解析；批量导入数量与列表一致。
- [ ] 关键文档状态已完成且切片数大于 0；失败和未开始的文档已处理。
- [ ] 抽查标题、数字、单位、表格、OCR 与例外条件；不准确的切片已修正或停用。
- [ ] 用固定问题集测试直接问法、改写、精确值、组合条件、版本冲突和无答案问题。
- [ ] 记录检索命中的文档、切片与所用参数；应用侧另行验证最终回答。
- [ ] 资料更新后先验收新版本，再停用旧版，并确认应用引用仍有效。
