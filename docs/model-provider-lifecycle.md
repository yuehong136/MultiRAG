# 模型配置的删除策略

本文件描述 Python 后端的厂商、连接实例与模型删除行为。生命周期入口为
`api/db/services/model_provider_service.py`；项目引用策略独立放在
`api/db/services/model_deletion_policy.py`。三个层级共用同一引用检查与请求事务。

## 当前规则

| 引用位置 | 是否阻止删除 | 处理方式 |
|---|---|---|
| 有效工作区默认设置、知识库、文档、聊天、记忆、搜索和技能检索配置 | 是 | 返回 HTTP 409、`MODEL_REFERENCED` 和具体资源清单；先更换模型 |
| Agent / 工作流当前 DSL | 是 | 先修改当前配置 |
| 每个 Agent / 工作流最新的已发布版本 | 是 | 当前公开运行使用此快照；修改草稿后还需重新发布 |
| 更早的发布版本、未发布版本历史 | 否 | 保留原始内容和模型引用 |
| 旧会话执行快照、流水线操作历史 | 否 | 保留原始内容和模型引用 |
| `status = "0"` 的已删除配置，以及所属知识库已删除的文档 | 否 | 不清空引用，不删除资源记录 |

当前发布版本与普通历史版本按运行入口的选择语义区分：使用
`release = true` 中 `create_time` 最新的版本；较新的草稿不会替代正在服务的发布版本。
最新时间戳相同或时间戳缺失、无法证明已经过时的发布版本保留保护。没有父 Agent 的
孤立历史版本不作为有效配置。文档的租户和可用状态从所属知识库判断。

有效共享消费者的数字模型 ID 仍受保护。跨所有者的引用清单不返回资源 ID 或名称，
仅提示存在共享引用；同名模型的名称别名只在对应租户内匹配。

## 删除后的行为

删除只移除请求范围内的模型注册及对应厂商/实例配置，不级联删除知识内容、聊天消息、
历史版本或运行快照，也不自动替换默认模型或改写历史。厂商删除影响其全部实例和模型；
实例删除影响其模型；单模型删除保留连接实例。

保留历史内容不代表保证历史可重放。再次运行旧会话、恢复或重新使用旧配置时，
其模型仍需存在且允许使用；按已经删除的数字模型 ID 读取会明确失败。应重新选择、
配置模型后再运行。不能通过自动切换到其他模型来伪造原模型仍可用。
此检查针对持久化配置，不是运行任务的排空或取消机制；它不承诺已发出的模型请求会被终止。

前端确认文案说明上述影响；409 清单仅展示仍阻止删除的有效消费者。本文的策略调整
不授权清理用户已有模型、历史或知识库。回归中的删除操作只针对独立 scratch 数据库。

## 参考与取舍

### 解析模型选择：保持六月阶段的 RAGFlow 合同

模型选择与删除保护是不同合同。知识库的 `parser_config.llm_id` 是保存的模型引用：
创建时复制当时的租户默认聊天模型，上传文档时复制知识库解析配置；运行时保存值优先，
缺失或空值才回退到当前租户默认聊天模型。更改租户默认值不批量覆盖已保存的值。
无法从旧值判断它来自自动复制还是用户指定，因此保留旧配置，不自动迁移或清空。

该合同并非十一月的新架构：

- [bd4eb193，2025-12-23，#12095](https://github.com/infiniflow/ragflow/commit/bd4eb193936949d8961ccbf55eb4a694a8fe9623)
  在 GraphRAG 配置前增加始终可见的“全局索引模型”，由 `LLMModelItem` 编辑
  `parser_config.llm_id`。独立 Web 对应 `GraphRagFormFields.tsx` 和
  `pages/knowledge/settings/configuration/common-item.tsx`；模型目录/选择器按本仓现有 API 适配。
- [e23c8a5d，2025-12-25，#12164](https://github.com/infiniflow/ragflow/commit/e23c8a5dcd4a460bdc40be29898ad02b7de8e25c)
  创建知识库时写入租户默认模型；本仓对应 `KnowledgebaseService.create_with_name()`。
- [4b0d65f0，2026-02-06，#13032](https://github.com/infiniflow/ragflow/commit/4b0d65f089f5ca728617f03773e8ef38566d65c7)
  区分文档和知识库解析模型。RAPTOR/GraphRAG 读取知识库值，普通文档解析读取文档值，
  两者缺失时回退租户值；本仓对应 `core/svr/task_executor.py`。

2026-06-12 的上游 `22a058f56cb39334539eea08ea37e243faf61a5d` 已包含以上行为。
此次补齐 Web 查看与编辑入口，不改变后端选择顺序、不新增模型来源字段或模式，
不提前移植八月后的 Go Knowledge Compiler 或组件级解析配置，也不推进逐提交跟进游标。
文档编辑入口复用现有 document PATCH：仅提交明确修改的叶子，不联动修改知识库；
知识库修改也不覆盖已有文档。仅更换模型保留已有解析结果，保存不自动重跑；改变解析方式
或管道时仍遵循现有重置语义。如需将新模型用于已有内容，由用户重新解析。
模型名称别名、数字引用、空值与缺失值继续兼容；不可用的旧模型仍显示，不因加载目录或无关保存而改写。

### 删除策略的后续源码对照（研究参考）

2026-11-13 核对以下上游提交，固定对照版本以便未来逐提交比较，而非宣称所有产品具有相同策略。
这些是删除策略的研究参考，不表示提前采用其模型选择或后端架构：

- [RAGFlow 厂商删除，e92f6df3](https://github.com/infiniflow/ragflow/blob/e92f6df3242de83d95222ab17c21f556f23c05f8/internal/service/model_service.go#L257-L317)：权限检查后删除其模型与实例，没有在该调用链遍历会话历史。
- [Dify 模型与凭据生命周期，3d364804](https://github.com/langgenius/dify/blob/3d364804fca9db45690e42d8e49b7cb90f4bbedf/api/core/entities/provider_configuration.py#L727-L814)：删除凭据时处理相关连接配置与缓存；[模型删除](https://github.com/langgenius/dify/blob/3d364804fca9db45690e42d8e49b7cb90f4bbedf/api/core/entities/provider_configuration.py#L1391-L1417)操作模型注册。
- [Open WebUI 历史版本切换，b0e6098e](https://github.com/open-webui/open-webui/blob/b0e6098e940942281d9c83f3529ea117287a3a22/backend/open_webui/routers/models.py#L876-L950)：使用历史版本前重新检查依赖；其[模型删除](https://github.com/open-webui/open-webui/blob/b0e6098e940942281d9c83f3529ea117287a3a22/backend/open_webui/models/models.py#L733-L751)有自己的关联清理范围，不等同于 MultiRAG 的历史保留需求。

MultiRAG 保留对有效消费者的防误删保护，避免破坏正在服务的知识库和发布配置；
同时解除纯历史和已删除配置对模型配置生命周期的永久锁定。该取舍不引入强制级联删除，
不复刻其他项目的存储结构或自动凭据回退。

## 跟进 RAGFlow 时的边界

上游目前是 Go 后端，本仓当前生产后端是 Python；跟进提交需要按行为移植，不能把
上游 Go 文件直接替换进来。厂商、实例、模型的删除顺序与接口职责继续放在现有生命周期
服务中，事务提交和错误映射仍由路由负责。项目策略通过 `require_unreferenced()` 这一个
调用边界接入，不扩散到供应商驱动、模型目录或模型执行实现。

`model_deletion_policy.py` 只返回有效阻塞引用，不删除数据、不提交事务、不发送 HTTP
响应。现有删除函数和错误信封保持兼容；前端只解释结构化引用清单，不重复判断哪些
历史应阻止删除。当前发布版本和文档父级状态是本仓运行语义，不能从上游删除函数中推断。

后续提交若只更新供应商、目录或连接适配，沿用上游变化；若涉及删除、模型标识、发布
版本或凭据生命周期，再对照上表核对。上游出现兼容改进时优先复用，保留确有业务依据的
项目差异。对应验证集中在 `test_provider_instances.py` 中的删除保护、历史保留、发布
版本和文档用例；无需为每个无关上游提交重复跑全部模型或真实供应商测试。
