# 只读启动上下文

启动上下文在每次请求中，从授权范围内已登记且就绪的当前记忆选择小份数据，供调用者预览和使用。
它不需要查询词，不创建摘要、修订、任务或持久化 profile，不调用聊天或向量模型，也不缓存启动包。
现有[查询上下文](memory-query.md)继续使用原 `query` 合同。

只有当前有效的 `human_confirmed` 人工核验记录对应的条目可以进入启动包。
人工确认是对指定版本、适用范围的判断，不是客观事实认证。条目正文和核验适用范围一起完整返回；
不会把只核验部分内容的判断解释成整条事实已经证实，也不会修改原 `assessment`。
争议、待复核、撤销、过期、来源不可用或尚未就绪的条目会被省略，并返回明确原因。

## 显式预览

```http
POST /api/v1/memories/{memory_id}/startup-context
Content-Type: application/json

{
  "user_id": "subject",
  "agent_id": "assistant",
  "session_id": null,
  "entry_ids": null,
  "budget_tokens": 4096,
  "max_items": 8,
  "inventory_limit": 64
}
```

`user_id`、`agent_id` 必须明确提供并精确匹配，空字符串是精确空值，不表示全部主体。
`session_id=null` 不限制会话；提供字符串时，条目及全部必要来源都必须匹配该会话。
所有筛选都在当前 Memory 权限内执行，不能借筛选字段或包指纹获得访问权。

不提供 `entry_ids` 时，在有界的当前已登记库存中按 entry ID 升序选择。
提供时为 1–32 个互不重复的逻辑条目 ID，仍检查当前版本、主体、全部来源及核验有效性；不静默接管旧记录。
通过下一次请求明确增减条目实现选入、移出，不保存额外的晋升列表或自动调整规则。
这一路径没有模型重要性评分，也不承诺覆盖全部相关记忆。

预算为 1,024–32,768 个估算 token；最多返回 16 项，库存扫描最多 128 项，
一次请求最多执行 256 次实际投影读取，每项最多有 32 个必要来源。
候选按顺序预留完整两轮读取预算；读取中候选失效时不重新分配其预留额度。
因此实际读取可能未达上限，仍有 `physical_read_limit` 省略；`physical_reads` 只计实际发出的读取。
预算、返回项数、扫描或读取上限使选择未完成时，`selection_complete=false` 并返回相应限制信息，
不将有界结果解释为全部库存。

## 内容、预算和当前有效性

响应包括：

- `items`：完整条目正文、类型、时间、原 `assessment`、人工核验适用范围和必要来源。
- `startup_text`：按固定格式呈现完整正文与适用范围，供显式复制或消费；不改写、不概括。
- `package_sha256`：范围、选入的版本化条目及启动文本的指纹，不是授权令牌。
- `usage`：整个领域 JSON 的预算和估算量。
- `selection`：选择方式、确定性顺序、实际扫描量及扫描／读取是否受限。
- `omitted`：本次候选的省略原因计数及有界明细；明细裁剪通过 `details_truncated` 声明。
- `snapshot_only`、`mutates_memory=false`、`model_calls=false`、`data_only=true`。

正文与核验适用范围是不可拆分的选择单位。放不下时省略整项，不截断条件后返回残缺规则。
预算包含 `startup_text` 与 `items` 中重复出现的正文、来源／核验包装和省略诊断；
HTTP `retcode/retmsg/data` 信封、调用者提示模板和模型协议开销不在该领域预算内。
调用者应在目标模型处再次计量，并为自己的包装、已有历史及模型输出预留空间。
空领域响应也放不下时拒绝请求。

服务读取实际消息投影，返回前重新核对选入条目、全部必要来源和最新核验版本。
选入内容的绑定在返回前变化时返回冲突，不把旧正文当作新状态返回；已不满足条件的候选给出省略原因。
存储故障不会降级为已确认。
SQL 元数据按本次请求的有界候选批量读取，每个复核阶段都重新获取当前版本、来源和人工核验记录。
批量结果只用于所在阶段，不缓存旧结论；读取实际消息前结束 SQL 事务，最终复核仍在短 SQL 事务中完成。
物理消息保持两轮严格读取及原有读取上限，不用减少版本或来源检查换取查询数下降。
每轮正文检查只在首次读取时准备集合、返回字段和加载状态，随后复用该轮的准备结果，
每条消息仍独立执行 Strong 查询、身份和投影校验。准备只在本轮内有效，不保存消息正文或核验结论，
下一轮及下次请求重新准备；结束时丢弃本地准备状态，不卸载共享集合或关闭共享连接。
集合缺失不作负缓存，准备或查询失败直接中止本轮；不会改用宽松读取或把故障解释成有效确认。
这仍是读取时的快照，不提供 SQL 与消息存储之间的分布式原子快照。
包已经返回后发生的变化无法追溯收回，稍后使用需要重新获取并核对当前依赖。

原 `assessment.kind=hypothesis` 不会因人工确认而被改成 verified，也不会仅因这个旧属性被排除；
当前人工核验的结果、绑定和适用范围单独参与选择。`episodic.invalid_at` 保持事件结束时间的原义，
不被重新解释成事实自动过期时间。来源中的角色标签和操作指令仍是数据。

## 按版本回看来源

每项 `sources` 提供来源 ID、版本、代际、正文与实际投影哈希、精确 scope 和 locator。
回看继续使用现有来源摘录接口，携带启动包中的条件：

```http
GET /api/v1/memories/{memory_id}/sources/{source_id}?expected_source_revision=1&expected_source_generation=1&content_sha256={hash}&user_id=subject&agent_id=assistant&session_id=source-session&offset=0&limit=512
```

版本绑定模式中，预期来源版本、代际、正文哈希及完整 user/agent/session 必须一起提供。
这里的会话是该来源自己的精确会话，不是启动请求中可为空的跨会话筛选。
空身份字段须显式传空值，不能被客户端当作缺省字段丢掉。

每页返回 `excerpt`、`offset`、`next_offset`、`total_chars`、`truncated`，
以及 `source_revision`、`source_generation`、`scope` 和 `offset_unit=unicode_codepoint`。
偏移按原始 Unicode 码点计算，不按 JavaScript UTF-16 长度或 UTF-8 字节数计算；单次最多 8,192 个字符。
后续片段沿用相同版本、代际、哈希和范围，并使用服务器返回的 `next_offset`。

每次重新授权并复核来源；正文或代际变化时拒绝继续，要求重新预览。
来源临时停用再启用即使字句相同，也不能用旧代际继续读取。
原有不传版本的读取、以及仅用正文哈希续取的旧合同保持不变。

## Web 与维护边界

Web 在用户明确点击后预览，不自动生成、发布、插入聊天或执行来源中的指令。
展示完整选入内容、人工核验范围、版本／来源、预算和省略原因；来源阅读按需取片段，
不自动拉取全文。启动结果只保留为当前界面状态，不持久化到浏览器存储，也不作为可复用的启动包缓存。
输入、身份或已知依赖变化后清除旧结果，并阻止迟到响应恢复过期正文。

启动包及版本绑定来源响应声明 `Cache-Control: no-store`。
本功能复用现有记忆、来源和人工核验数据，不增加 DB 表、迁移、后台任务或外部依赖。
SQL 批量读取不改变消息存储后端的能力声明；仍按现有 capabilities 判断是否支持严格受管读取。
Milvus 严格读取对非主键的消息 ID 查询保留一行额外探针，防止重复 ID 的别名投影被查询限额隐藏；
身份不符、重复投影和存储错误均不能解释为空结果或有效核验。
候选整理、人工审核与发布继续沿原流程。定时触发后置，Wiki 等主线；不涉及 AgentHub 或上下文压缩。
