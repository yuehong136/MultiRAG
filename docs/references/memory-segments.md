# 来源分段与完整覆盖

分段整理复用[增量计划](memory-incremental.md)、维护 worker、候选与[人工审核发布](memory-maintenance.md)。
它将一个已登记来源的当前版本分为有界片段，分别提交现有维护任务。
整条来源只有在所有必要片段有效分析并结算后，才计为已覆盖。

## 显式启用

旧请求继续使用完整来源模式。预览和创建计划时可加入：

```json
{
  "segmentation": {
    "mode": "segmented",
    "fragment_token_limit": 2048,
    "max_parts_per_source": 32
  }
}
```

其余 scope、策略、旧 entry、预算、预览哈希和操作 ID 字段保持原合同。
`fragment_token_limit` 为 256–8,192，`max_parts_per_source` 为 1–64，默认分别为 2,048 和 32。
每个计划最多 256 个主要片段；每次 runs 仍显式提交最多 8 个子任务。
模式和分段参数进入分析配置指纹，完整来源模式保持原配置身份。

完整来源预览只按版本元数据选源，`token_fit=not_checked`。
分段预览会读取 RAW 正文并校验来源绑定，规划片段并检查序列化分析输入预算，返回 `checked_at_preview`。
两种预览均不创建任务、不写覆盖账本、不调用模型；子任务创建和执行时仍重新检查来源、权限及预算。

显式选入旧 entry 时，其必要来源继续作为完整上下文，计入子任务来源容量与输入预算。
这些上下文来源不再同时充当本计划的分段主要来源，也不因重复带入而增加新覆盖量。
上下文本身放不下时明确延期或拒绝，不静默截掉目标正文或必要依据。

## 片段身份与位置

片段描述包含：

| 字段 | 含义 |
| --- | --- |
| `fragment_id` | 绑定来源版本、分段器、位置及正文哈希的稳定身份 |
| `part_index` / `part_count` | 从 0 开始的序号与完整片段数 |
| `core_start` / `core_end` | 本片负责覆盖的原文半开区间 |
| `read_start` / `read_end` | 实际送入分析的原文区间，含有界邻接上下文 |
| `core_sha256` / `read_sha256` | 覆盖正文与实际读取正文各自的哈希 |
| `offset_unit` | 固定为 `unicode_codepoint` |
| `splitter_version` | 服务端分段算法标识 |

位置针对解码后的原始 Unicode 字符串，不是 UTF-8 字节、JSON 转义后的字符或 JavaScript UTF-16 长度。
覆盖区间从 0 到原文末尾连续、不重叠；邻接读取范围前后各最多延伸 64 个码点，只提供上下文，不重复计入覆盖。
分段优先选择段落或句界，并以完整输入估算预算及片段正文预算检查切点；必要时使用有界切点。
邻接上下文有长度限制，不能保证远距离条件、否定或跨片关系都被模型保留。

候选来源和已发布修订的来源 locator 保留片段依据；`content_sha256` 仍表示整条来源正文哈希。
撤回或修改整条来源会影响所有依赖片段，不能因某个片段的局部文字未变化而忽略来源代际变化。

## 完成与恢复

覆盖账本分别保存来源版本和片段处理证据。一个片段只有在以下条件同时满足时才有效完成：

- 当前来源 revision、generation、正文哈希及分析配置匹配。
- 宿主接受完整分析结果；合法空提议也可以完成分析。
- 关联任务就绪，execution 为 succeeded，实际 writer 调用已排空。

一个成功片段不能让整条来源提前完成。坏回包、取消、延期、结果未知或尚未排空都不算有效片段。
跨任务恢复复用同配置下仍有效的完成片段，只重新安排未完成片段；旧句柄失去片段归属后不能继续产生有效结果。
请求断开时先读取原计划，显式重放原操作；刷新和轮询不会自动提交或调用模型。

Web 分别展示来源版本数、片段数与子任务数。计划选源统计保持封存，`source_coverage` 表示服务端重新判断的计划覆盖；
需要查看当前范围所有来源的覆盖，仍应显式重新预览。
覆盖表示已分析，不表示候选正确、跨片关系全部整理、已批准或已发布。

## 有界延期

来源正文超过 1 MiB、单来源片段数超限、计划片段数超限、完整上下文超预算或没有片段能放入预算时，返回明确原因。
底层消息存储自身的正文大小限制仍适用。
超限时不把前若干片段冒充整条覆盖；单来源在同配置下的已知阻塞不会一直占据后续可选来源窗口。
仅因本计划达到 256 个片段而延期的来源仍可被后续窗口选择，不记为永久阻塞。
可缩小范围、调整预算或分段参数后重新预览，不靠删掉尾部文字换取完成。

## 部署与验证

先备份并应用正式 Alembic 迁移，再统一切换 API 与维护 worker。
新增数据为片段覆盖元数据、来源覆盖计数和输入的可空片段描述；旧完整来源输入不需要补造片段。
来源与整库删除继续沿既有停供、排空和正文清理协议；片段哈希及范围属于保留的审计元数据。

固定回归区分精确 Unicode 覆盖、跨批显式旧记忆对照和真实模型语义效果。
真实模型工作负载另计来源向量化、分析、发布向量化、检索向量化及回答的所有已观察调用，失败未知用量不记作零。
本功能不提供定时触发、自动审核发布、自动跨批语义合并或 Wiki。
