# 人工核验与争议待办

人工核验为已登记的当前记忆保存独立结论。它记录某位获授权的人对指定版本、适用范围和依据的判断，
不证明外部事实必然正确。核验不会修改记忆正文、向量、原 `assessment` 或启停状态，
也不代替 [Dreaming 候选审核和显式发布](memory-maintenance.md)。

人工确认、候选批准采用和来源引用检查分别表达不同含义：

- `human_confirmed`：核验人明确确认绑定版本在所述范围内适用。
- `disputed`：核验人登记争议及其依据。
- `needs_review`：核验人明确要求继续复核。

方法、适用范围、说明和证据引用都是人工提供的数据。接口不联网核查引用，不执行工具或代码，
不调用聊天或向量模型，不接受客户端覆盖认证身份、租户或记忆的验证属性。
`source_comparison`、`external_check`、`other` 是核验人报告的方法；选择 `external_check` 不会使服务执行外部检查。

## 读取与明确提交

先检查 Memory 的 `capabilities`，再读取
`GET /api/v1/memories/{memory_id}/entries/{entry_id}/verification-snapshot`。
快照返回完整当前正文、版本、来源依赖及绑定指纹，供用户审查；不会自动登记来源、接管旧记忆或创建核验。
来源仍通过既有[来源读取接口](memory-query.md)按权限和版本回取。

提交使用 `POST /api/v1/memories/{memory_id}/entries/{entry_id}/verifications`，
携带原操作 ID、快照的 `expected_binding_sha256` 和 `expected_head_version`，
以及人工结论、方法、适用范围、说明和证据引用。
服务器重新核对授权、当前版本、来源状态及实际投影，再保存核验记录。
任何前置条件变化都须重新读取快照并由用户重新审查，不悄悄改为针对新版本的结论。

```json
{
  "operation_id": "human-check-project-port",
  "expected_head_version": "0",
  "expected_binding_sha256": "<verification-snapshot 返回的 64 位哈希>",
  "result": "human_confirmed",
  "method": "source_comparison",
  "applicability": "只核对当前项目端口，不核对外部系统实时状态。",
  "notes": "已人工对照当前来源和记忆正文。",
  "evidence": [{"description": "项目决定记录", "reference": "source:900"}]
}
```

首次 `expected_head_version` 为 `"0"`，后续使用当前快照返回值。
物理 ID、来源 ID、版本、代际和核验序号在新接口中使用规范十进制字符串；逻辑 ID 保留字符串。
适用范围必填，最多 1,024 字符；说明最多 2,048 字符；证据最多 8 条，每条描述和引用各最多 1,024 字符。
每条记忆最多绑定 32 个必要来源，超限时拒绝，不丢弃依据后继续记录。

每条记忆只有一个最新核验指针；后续核验通过版本比较替代该指针，历史仍保留。
人工报告的核验时间与服务器保存时间分别记录，不能把客户端提供的时间当作可信工具执行回执。
省略 `checked_at` 时默认使用提交时刻，`checked_at_is_user_reported=false`；这也不表示系统执行了事实核查。

## 失效与撤销

核验绑定当前逻辑版本、代际、正文及实际投影摘要，以及全部必要来源的版本、代际、范围和摘要。
记忆或依据改变后，旧结论不能继续显示为对当前版本的人工确认；即便正文后来改回相同字句，也须重新核验。

读取返回的有效性只对应本次核对。它不是 SQL 与消息存储之间的分布式原子快照，
已经返回给调用者的内容也不能追溯收回。只读查询不会更新核验记录或自动发起复核。
`result` 保留当时的人工结论，`effective_status`、`valid_for_current`、`stale_reasons` 表达当前有效性；
调用者必须一起检查。操作 `status=ready` 只表示核验事件已保存，不代表记忆事实已经证实或候选已经发布。

显式撤销通过 `POST /api/v1/memories/{memory_id}/verifications/{verification_id}/revocations`，
携带原操作 ID、预期最新核验版本和原因。撤销不修改记忆正文，不撤销已经完成的候选发布。
重新核验使用当前快照提交新记录，不能通过恢复旧结论越过来源或记忆版本变化。

来源永久撤回、记忆遗忘及整库删除沿现有失效与清理协议处理核验中的说明、证据和适用范围。
最小审计身份、版本和哈希与正文清理分别表达；备份和调用者已取得的副本不在全部物理抹除保证内。
撤回后的正文不通过历史、原操作或列表重新暴露。整库删除后普通核验接口返回 404；
SQL 保留的最小核验审计元数据不构成新的删库后公开读取入口。

## 待办、历史与恢复

`GET /api/v1/memories/{memory_id}/verification-todos` 只列每条记忆最新的争议、待复核、已过期或被撤销结论。
撤销只移除原人工结论，不表示争议已解决；它仍作为当前待复核项，直到明确提交新核验。
已被新结论替代的历史不反复进入待办。列表有扫描和页大小上限，续页须保持相同筛选；
达到核对上限时保留明确的限制信息，不能将有界查询解释为全库没有争议。
待办默认每页 10 项、最多 20 项，每次最多扫描 64 个最新核验指针、执行 256 次实际投影读取。
响应包含 `items`、`next_cursor`、`has_more`、`scan_limited`、`scanned_count` 和 `snapshot_only`。

`GET /api/v1/memories/{memory_id}/entries/{entry_id}/verifications` 读取核验历史。
历史默认每页 20 条、最多 50 条，按记录版本倒序续取；历史结论不被当作当前有效结论。
每次查询和命令都重新检查当前 Memory 权限；内容主体筛选不能授予资源访问权。

所有命令使用稳定 `operation_id`。同一操作、身份和请求重放返回原受理结果，
不能因为后来正文改变而把同一操作重新用于新版本。
提交结果未知时通过 `GET /api/v1/memories/{memory_id}/verification-operations/{operation_id}`
读取原结果；未知不能当作没有提交，不能换 ID 盲目重发。

Web 复用记忆详情，提供核验快照、明确提交、历史和撤销；争议待办可恢复到对应记忆。
刷新与轮询只读，不自动确认事实、解决争议、改写正文或发布候选。

## 维护边界

核验实现与 SQL 元数据独立于上游消息 schema，复用当前权限、来源、修订和失效接点。
部署前应备份并应用对应正式迁移，统一切换 API 与相关 worker；源码交付和隔离验证不代表业务库已迁移。
新迁移只增加独立核验表，不把已有记忆自动标记为人工确认。核验表非空时拒绝通过降级迁移丢弃审计记录，
不要为回退程序版本而清空核验历史。
定时触发继续独立后置，Wiki 等待主线；本功能不涉及 AgentHub、启动上下文或压缩。
