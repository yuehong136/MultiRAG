# Memory 小规模效果与成本基线

基础集使用八个中文合成案例，另有八个补充回归与六个留出案例，检查偏好条件、局部纠错、跨会话决策、多来源依赖、主体隔离、坏输出与保守放弃。
上述 22 例候选对照的输入只来自 fixture，不读取业务聊天；有效候选只在内存中模拟应用，不写入消息存储。

## 比较范围

A 是已有精选 entry，B 是经过生产候选校验、在内存中应用有效提议后的 entry。RAW 证据仍可检索，
该候选对照没有运行检索回答器，因此不测真实问答准确率，也不能用正文覆盖增量推断 RAG 收益。

自动评分仅将完整匹配的预定义 oracle 正文映射到事实 ID，再核对来源绑定及兄弟事实。
合法的改写留给语义复核；引用、否定或只包含相同关键词不能自动算作掌握事实。
`valid_candidates`、`explicit_noop`、`no_proposal`、`mechanism_rejected` 和 `analysis_failed` 分别报告。
没有提出候选不能一律计为正确；模型安全放弃也不能冒充成功触发了主体隔离等宿主门禁。

## 运行与重放

fixture 为 `tests/fixtures/memory_maintenance_baseline.json`、`memory_maintenance_holdout.json` 和
`memory_maintenance_unseen.json`；纯评分与注入接口在 `memory/maintenance/evaluation.py`。
调用 `run_baseline` 时注入生产分析器和实际 tokenizer，并保存逐案例、逐尝试观察记录。
基线回调必须在失败时仍返回已知 token 和耗时；不可得的用量保留 unknown。

`tests/manual/memory_maintenance_baseline.py --reference-oracle --out <新私有报告路径>`
只检查人工编写 oracle 与评分工具能否协同工作，不调用真实模型，不是效果证明。
使用 `--observations <观察JSON>` 可重放已经保存的模型结果，`--prices <报价JSON>` 可附带有来源与日期的价格。
本地运行须通过[登记入口](../development.md#事前登记验证命令)，报告路径事前登记且不能覆盖旧失败。

观察记录区分 provider 返回的总 token、输入/输出/缓存细分、估算预算、elapsed、模型与配置指纹。
总 token 不能凭比例拆成输入输出，输出上限不能当实际输出；缓存或价格缺失时金额为 null。
报价需包含币种、来源、日期及各适用桶的单位价。参考估价、供应商返回金额和实际核对的账单分开，
未核账单时不标记 billing verified；未报告的 SDK 内部重试也不能假定不存在。

## 真实模型对照与限制

2026-11-15 使用配置中的 `qwen-flash`、生产 `MaintenanceAnalyst` 和宿主候选校验比较旧、新选择提示。
实际共享环境的锁定 LiteLLM 已修复，不使用临时依赖覆盖。
各组使用相同来源正文、entry、策略、预算和模型配置指纹；仅切换系统提示。
原始八例及 oracle 未改。补充八例最初独立编写，随后用于分析问题，因此最终比较中属于调优回归；
六个留出案例在新提示冻结后由独立审阅者编写，未用于调整提示。现已保存为固定回归，未来不能继续称为未见样例。
oracle、参考提议和语义审阅记录都不进入模型请求。

每例输出上限 2,048 token，显式关闭本次客户端的 provider/SDK 重试；每例观察到一次调用。
供应商内部重试不可见，响应只返回模型别名，不能据此证明服务端模型权重版本永久不变。
包含中间探索结果共 60 次调用，全部保留原始观察和失败分类，没有自动审核或发布。

| 案例集 | 旧提示：有效候选 / 无提议 / 宿主拒绝 | 新提示：有效候选 / 无提议 / 宿主拒绝 |
| --- | --- | --- |
| 基础 8 例 | 2 / 6 / 0 | 8 / 0 / 0 |
| 补充回归 8 例 | 0 / 5 / 3 | 7 / 0 / 1 |
| 最终留出 6 例 | 0 / 3 / 3 | 4 / 0 / 2 |

这里的“有效候选”仅表示宿主结构和依赖校验通过，**不是语义成功或准确率**。
独立语义复核确认了具体改善：带条件偏好不再空缺；部分跨会话决定能保留；
已有条目的修订可补齐新旧来源，并保留同条记忆中的其他事实。
六个留出案例中，条件偏好、扫描格式的完整来源修订、词典压缩定案与校验步骤这三例有明确改善。
正确的分开记录也能保留事实，不强制要求单段合并才算有用。

仍有需要审核拒绝或修正的结果：补充回归把已定案的压缩方式误写为待定；
一次撤回决定的修订漏列旧来源，被宿主拒绝；留出案例中混合两个主体的提议和虚构目标 entry 的修订也被拒绝。
一次性请求、攻击引文和空泛猜测仍可能形成低价值候选；个别理由或措辞还会超出来源。
未验证标签不能使错误正文变正确，宿主拦截也不意味着模型已经理解了主体隔离。
因此这些结果支持保留人工审核的有限增量，不支持“跨会话决策已可靠”或自动采用。
合法改写和标点变化可能不命中完整正文 oracle，必须结合语义审阅，不能把未识别一律记为事实丢失。

## 真实模型完整记忆流程

显式基线在 `tests/evals/test_memory_workload.py`，复用生产 HTTP、SQL、消息存储、维护 worker、候选校验、审核与发布。
仅使用合成数据与独占 scratch 租户；已配置模型只读解析后复制到 scratch，内部用量计数也只更新 scratch 模型行。
当前已验证 `qwen-flash` 与 `text-embedding-v4` 的通义路径，调用使用现有锁定依赖。

工作负载分别记录来源向量化、候选分析、发布向量化、检索向量化和回答的每次已观察 SDK 调用。
原始 usage、缓存细分、请求输出上限、耗时、模型与配置快照保留；失败或缺少用量不补零。
模型输出进入 pending 候选，生成独立 review request；外部复核文件绑定候选摘要与明确选择，随后才通过审核、发布 API 采用。

## 旧记忆推荐的纵向回放

`tests/fixtures/memory_target_longitudinal.json` 与显式入口 `tests/evals/test_memory_target_longitudinal.py`
保存四类已知合成案例：纠正已发布旧内容且保留兄弟事实、旧决定晚到、新增否定与适用条件，以及相似内容属于不同主体。
它们是固定回归，不是未见样例或业务数据。

每例先通过真实 RAW 入库、维护分析、独立候选复核和发布建立旧 entry，再按需通过人工修订 API 构造明确的旧记忆 fixture。
这一步人工编写的旧正文属于受控准备，不计作模型提炼效果。随后才导入新会话，调用生产目标推荐接口，
显式选定目标及版本前置条件，复用增量计划、后台分析、独立候选复核、审核发布、检索和回答。
模型请求不包含期望答案、oracle 或独立复核结论。

分别观察旧目标是否召回、其他主体是否排除、分析前后是否未自动写入、修订是否保留条件与其他事实，以及最终检索答案。
模型没有必要修改旧条目时允许复核明确拒绝全部候选；不能为了增加“成功发布”数量而强行改写。
结构合法和目标被找回仍不能代替独立语义复核。
检索上下文可能同时包含 RAW 证据与当前已发布条目；回答正确不能单独归因于新增记忆，需另核对实际 current 修订及引用。

每次实际 SDK 调用额外记录 `workload_phase`，将旧数据准备、推荐查询向量化、后续分析/发布和检索回答分开。
阶段总计仍覆盖所有已观察调用，包含失败；已知旧数据准备费用不能隐藏在后续增量处理费用之外。
引用报价、用量未知、供应商不可见重试和未核账单的限制继续适用。
真实评估仍需显式 opt-in、登记命令和独占 scratch 环境，不自动加入默认质量或生成套件。

2026-11-16 的初次纵向回放中，跨主体案例正确召回本主体目标并排除另一主体，但因 patch 来源闭包不完整被宿主拒绝。
随后同策略定向诊断保留了实际回包：patch 只引用新来源，把必要旧来源放在另一条 noop 中。
保留这两次失败及用量，没有将整批提议的来源并集补给单条 patch，也没有放宽校验。
只增加文字说明的 434-token 策略在首例仍遗漏旧引用，因此也保留失败，没有把它写成有效修复。
最终由宿主为模型输入中的每个旧目标派生 `required_source_input_ids`，直接列出已有必要来源对应的输入 ID，
模型须将它们列入该条 patch 的引用。缺失或歧义映射在模型前拒绝；省略正文的输入不会因有 ID 而变成可用证据。
宿主仍逐条校验模型输出，不补填回包，也不以整批引用并集代替单条依赖。
完整派生 JSON 同时用于预算估算和实际分析；输入合同进入策略指纹，旧增量计划不能冒充新策略覆盖。
原 512 预留和至少 52 token 协议余量的测试保持不变，不提高输入或输出预算。
旧 22 例真实模型成绩属于此前策略，不冒充这次澄清后的真实复验。

## 只读启动包的真实纵向回放

模型 ID 由本机配置指定，不能以厂商标签替代实际解析出的模型和端点核对。
仍须通过登记入口、`eval-generation` 显式文件目标和 `--include-external-consumer` 执行，

1. 真实来源入库、模型分析产生 pending 候选，经独立语义复核后才明确审核发布。
2. 未确认版本的启动包为空；独立复核当前核验快照及完整适用范围后，才模拟提交 `human_confirmed`。

回答语义审阅在原始报告之外保存独立记录，按各阶段实际来源判断，不把最终更正值套到早期阶段。

### 完整消费请求预算

`tests/support/memory_startup_evaluation_budget.py` 检查 OpenAI SDK 序列化后实际 HTTP 请求体中的完整消息和请求字段，
覆盖系统提示、问题、实际历史、启动数据、检索数据及包装，并加上输出预留与安全余量。
门禁在模型 bundle 构造前安装，位于 HTTP 发送边界，覆盖实例绑定和 LiteLLM 缓存的 raw-response 方法；
超预算在发出模型请求前拒绝。认证头和传输选项不作为模型上下文计数。
固定回归使用真实 OpenAI 适配器与 SDK、受控 HTTP 响应验证预算和用量均能观测到，超预算时没有实际发送。

启动领域 JSON 的预算与调用者总预算分开报告；领域 JSON 已被消费时不再把其 token 重复加到账上。
本次 startup 分支消费完整领域 JSON，因此 `items` 与 `startup_text` 中的重复正文也计入实际输入。
每个消息明确归类，分项计数仅用于诊断，不能将非可加的 tokenizer 分项冒充精确总数。
计量使用 `cl100k_base` 估算，报告实际供应商 prompt token 与估算差额；不宣称它是 Terra 的精确 tokenizer。
本次显式调用者总预算为 16,384，输出预留 512，安全余量 256，不以本机模型目录的最大窗口替代工作负载预算。

两分支使用同一阶段的检索字节和相同总预算／输出上限，不因存在启动包就删除尚未实际送出的检索事实。
当前回放没有历史消息，历史分量为零；预算单测另外覆盖非空历史和包装。
这是增量加入启动包的对照，不是只允许模型读取启动包的消融，也不能单独证明答案正确来自新增启动内容。
共享的准备、提炼、发布和检索只在整次回放中计一次，回答调用按分支分别记录；
不能把它解释成两条各自独立完成全部准备的生产成本。
